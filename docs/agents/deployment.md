# Deployment

`packages/infra/alchemy.run.ts` defines the Cloudflare resources (the TanStack Start Worker, D1, the `comics` and `downloads` R2 buckets and the Watermarker container) and the migrations folder Alchemy applies on deploy.

- Never run `pnpm deploy`, `pnpm destroy` or `alchemy` commands unless asked; they change real Cloudflare resources.
- `pnpm deploy` runs with `APP_ENV=production` and defaults to a personal `dev_<username>` stage. Production uses an explicit stage: `cd packages/infra && pnpm exec alchemy deploy --stage production`.
- GitHub Actions deploys (`.github/workflows/ci.yml`, job `Deploy`, after `Check` passes): a push to `main` deploys stage `production`; each open same-repo PR deploys stage `pr-<N>` and comments its URL on the PR. Closing the PR destroys the preview (`preview-cleanup.yml`). Fork PRs are not deployed. Both run `alchemy deploy|destroy --stage <stage>` with `APP_ENV=production`, one at a time per stage.
- The workflows read the same secret names from two GitHub Environments: `preview` (Stripe **test** keys) and `production` (Stripe **live** keys). Each needs `CLOUDFLARE_API_TOKEN`, `CLOUDFLARE_ACCOUNT_ID`, `ADMIN_EMAIL`, `EMAIL_FROM`, `BETTER_AUTH_SECRET`, `STRIPE_SECRET_KEY` and `STRIPE_PUBLISHABLE_KEY`. The workflows also pass `STRIPE_SECRET_KEY` as `STRIPE_API_KEY`, which Alchemy's Stripe provider reads; it is not a separate secret. Destroying a preview needs the same secrets, to delete its Stripe endpoints.
- A deployed stage names its Worker `garage-comics-web-<stage>`, so its URL is `https://garage-comics-web-<stage>.<subdomain>.workers.dev`, with the subdomain from `CLOUDFLARE_WORKERS_SUBDOMAIN` (a GitHub repository variable, not a secret; Alchemy reads it too). Set it as well to deploy from your machine.
- Each deployed stage creates its own two Stripe webhook endpoints (`/api/stripe/webhook` and `/api/stripe/connect-webhook`) at that URL **before** the Worker, and passes their signing secrets to it as `STRIPE_WEBHOOK_SECRET` and `STRIPE_CONNECT_WEBHOOK_SECRET`; destroying the stage deletes them. Never set those two in GitHub or `.env.production`. Under `alchemy dev` no endpoint is created and both come from `.env`. Never build the endpoints from the Worker's own `url` and `bind()` the secrets back: Alchemy uploads the Worker before that binding resolves, and both secrets reach it empty.
- Stripe returns a signing secret when it creates an endpoint. If a later deploy stops with `has no signing secret in state`, give the affected endpoint a new logical ID. Alchemy creates the new endpoint and updates the Worker before it removes the old endpoint tracked in state. Check the stage's Stripe destinations for an orphan if the failed deploy left an endpoint outside Alchemy's state. The endpoint metadata identifies the stage and logical ID.
- `patches/@alchemy.run__stripe@2.0.0-beta.85.patch` compares the create-time `connect` flag against the saved configuration. Stripe's nullable `application` field can make the unpatched provider incorrectly replace a Connect endpoint on a later deploy. To change an existing endpoint's Connect mode, give it a new logical ID. With the same ID, Alchemy beta.85 can reuse the old endpoint during replacement and lose its signing secret.
- `apps/web/cloudflare-env.d.ts` is hand-written; it infers Worker binding types from `alchemy.run.ts`.
- The Worker's `main` is `apps/web/src/server.ts`, which wraps Start's handler and exports the `Watermarker` Durable Object class. Cloudflare finds a Durable Object class only among the entry's exports.
- The `comics` bucket holds covers and PDFs. Browsers upload parts straight to it through presigned URLs, so its CORS allows any origin; the Worker reads and signs with the `COMICS` binding and the `COMICS_S3` credentials (a bucket-scoped API token Alchemy mints on deploy). Under `alchemy dev` both run against a local emulation.
- The `downloads` bucket holds only watermarked copies; its lifecycle rule deletes every object a day after it is written, so originals must never go there. A Download Link's 24 hours are enforced in D1, not by the rule.
- The Watermarker container (`containers/watermarker`, Python with pikepdf) needs the Workers Paid plan. `alchemy dev` builds and runs it with local Docker, so start Docker before `pnpm dev`. The image build runs `stamp.py --self-check`. After changing `stamp.py`, run `python3 containers/watermarker/fixture/measure.py` (needs pikepdf and poppler) and keep every page passing.
- `WATERMARKER` is typed from the `WatermarkerRpc` interface in `alchemy.run.ts`, which the class implements. Never type the binding with the class itself: `Cloudflare.Env` then depends on itself and other bindings silently become `any`.
- `patches/@alchemy.run__cloudflare@2.0.0-beta.85.patch` fixes an Alchemy bug: a `Website.Vite` build resolves every Effect in `env` to inline `VITE_*` values, including `R2.S3Credentials`, which then fails the deploy with `Service not found: Cloudflare.Workers.WorkerEnvironment`. The patch skips it, as Alchemy already does for `Container`. Still unfixed in 2.0.0-beta.87; when upgrading Alchemy, check whether `resolveViteEnv` in `Workers/Sources/Vite` skips `isS3Credentials` and drop the patch if so.
